# Manual Cycle Contract

Manual cycles are the current safest way to use `spec-devloop`.

A manual cycle represents one bounded development step whose intent, execution result, and evidence can be inspected by humans and tools.

Manual mode is important, but it is not the final operating mode of the project. It is the first supported mode and a fallback for cases where full automation is not desired.

## Purpose

A cycle helps answer:

- What was the task?
- What was the expected outcome?
- What was changed?
- What evidence was produced?
- Was the result accepted, rejected, blocked, or sent back for correction?

## Current MVP-0 cycle layout

```text
.ai-loop/cycles/<cycle-id>/
├── meta.yaml
├── task.md
└── report.md
```

## `meta.yaml`

Example:

```yaml
schema_version: "0"
cycle_id: c-001
created_at: "2026-05-26"
status: planned
```

Required fields:

- `schema_version`;
- `cycle_id`;
- `created_at`;
- `status`.

Accepted status values:

- `planned`;
- `ready_for_worker`;
- `in_progress`;
- `waiting_review`;
- `completed`;
- `blocked`.

MVP-0 validates status values but does not execute transitions.

## `task.md`

Describes the intent of the cycle.

It may include:

- goal;
- scope;
- files likely involved;
- acceptance criteria;
- constraints;
- notes for the worker.

## `report.md`

Describes the result.

It may include:

- what changed;
- tests run;
- files modified;
- problems found;
- pending work;
- suggested next step.

## Optional future files

```text
plan.md
worker.md
evidence.md
review.md
```

### `plan.md`

Supervisor or human plan before execution.

### `worker.md`

Worker-facing instructions generated by the supervisor.

### `evidence.md`

Logs, tests, command output, diffs, screenshots, or other proof of execution.

### `review.md`

Supervisor review of the evidence and final decision.

## Current commands

### `devloop cycle list`

Lists cycle directories.

### `devloop cycle check <cycle-id>`

Validates the minimum cycle contract.

It is report-only:

- does not create files;
- does not modify files;
- does not call models;
- does not call agents;
- does not execute commands.

Exit codes:

- `0`: valid;
- `2`: validation error;
- `3`: internal error.

### `devloop cycle prompt <cycle-id>`

Emits a Markdown context packet for manual execution.

This is useful in manual mode but should be understood as a compatibility/fallback mechanism, not the final product goal.

### `devloop cycle summary <cycle-id>`

Prints a compact summary:

- cycle id;
- status;
- created_at;
- required files;
- optional files;
- error count.

It reuses cycle validation and remains report-only.

## Relationship to future modes

The same cycle concept should support:

- manual mode;
- agent plugin/protocol mode;
- autonomous orchestrator mode.

Future versions may create, update, execute, review, and close cycles automatically, subject to policy and human checkpoints.
